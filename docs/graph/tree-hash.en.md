When determining whether some trees are isomorphic, we often convert these trees into hash values and store them, in order to reduce complexity.

Tree hashing is very flexible; various hashing methods can be designed. But if designed arbitrarily, it may well be wrong and may be broken (hacked). Below we introduce a class of methods that is easy to implement and not easily broken.

## Method

This class of methods requires a hash function for a multiset. The hash value of the subtree rooted at a certain node is exactly the hash value of the multiset formed by the hash values of the subtrees rooted at all its sons, i.e.:

$$
h_x = f(\{ h_i \mid i \in son(x) \})
$$

where $h_x$ denotes the hash value of the subtree rooted at $x$, and $f$ is the hash function of the multiset.

Taking the hash function used in the code as an example:

$$
f(S) = \left( c + \sum_{x \in S} g(x) \right) \bmod m
$$

where $c$ is a constant, generally just use $1$. $m$ is the modulus, generally use $2^{32}$ or $2^{64}$ for natural overflow, and a large prime can also be used. $g$ is a mapping from integers to integers; the code uses xor shift, and other functions can also be chosen, but using polynomials is not recommended. To prevent the problem setter from breaking the xor hash, we can also xor a random constant before and after the mapping.

This kind of hash is very easy to write. If rerooting is needed, during the second DP we only need to subtract the subtree hash.

### [\[BJOI2015\] Tree isomorphism](https://www.luogu.com.cn/problem/P5043)

The isomorphism mentioned in this problem refers to that of unrooted trees, while the method introduced above is for rooted trees. Therefore, only when the roots are the same are the hash values of two isomorphic unrooted trees the same. Since the data range is relatively small, we can brute-force compute the hash value when rooted at each point, then sort and compare.

If the data range is relatively large, we can also use rerooting DP, traversing the tree twice, to find the hash value when rooted at each point. We can also use the above multiset hash function: store the hash values when rooted at each node into a multiset, then compute the hash value of the multiset, and compare (approach one).

We can also optimize the complexity by finding the centroid. A tree has at most two centroids; we only need to find the hash value when rooted at it (them). Next, we can either compare these hash values separately (approach two), or when there is one centroid, take its hash value as the hash value of the whole tree, and when there are two, take the smaller (larger) of them.

### [HDU 6647 Bracket Sequences on Tree](https://acm.hdu.edu.cn/showproblem.php?pid=6647)

The problem asks for the number of essentially different bracket sequences generated by traversing an unrooted tree.

First, we can note that two non-isomorphic rooted trees will definitely not generate the same bracket sequence. We first consider the number of essentially different bracket sequences that traversing a rooted tree can produce. Assume the root node of the subtree we are currently considering is $u$, and denote $f(u)$ as the number of schemes of this subtree; starting from $u$ and traversing downward, the order can be chosen arbitrarily, producing $|son(u)|!$ permutations, and traversing each son node $v$, there are $f(v)$ schemes in the subtree of $v$, so we have $f(u)=|son(u)|! \cdot \prod_{v \in son(u)} f(v)$. But, isomorphic subtrees produce duplicates, and $f(u)$ needs to be divided by the product of the factorials of the occurrence counts of each essentially different subtree, similar to the permutation of a multiset.

Through the above DP, we can find the number of schemes of the root node. Then through rerooting DP, transferring the hash value and scheme information of the parent node to the son, we can find the hash value and number of schemes when rooted at each node. Each different subtree only needs to be counted once.
